# Mathis Operation Process

## 1. 文档概述

- 来源：`260323_Mathis_UI_Operational_Logic-V1.6.xlsx`
- 基准版本：V1.6
- 目的：将工作簿中的 UI 操作逻辑整理为便于产品、固件和测试共同使用的操作流程说明。
- 说明：本文以 `Operation Process` 工作表为规范基准；`Bugs and Improvements` 中的内容单独列为待确认/待修正项，不直接覆盖正式流程。

## 3. 总体运行流程

```mermaid
flowchart TD
    A["设备关闭"] -->|按下 On/Off [1]，任意持续时间| B["设备开启"]
    B --> C["默认显示 D 表面温度<br/>点亮 D 指示 [8]"]
    C --> D{"用户操作或状态变化"}
    D -->|短按 On/Off [1]| E["切换可用温度读数"]
    D -->|插入探针 [5]| F["切换至探针温度<br/>点亮 Probe [6]"]
    D -->|短按 Bluetooth [2]| G["切换 °C / °F"]
    D -->|长按 Bluetooth [2] ≥1 s| H["进入蓝牙配对"]
    H -->|2 min 内成功| I["蓝牙已连接<br/>指示灯常亮"]
    H -->|2 min 内未成功| J["关闭蓝牙<br/>指示灯熄灭"]
    I -->|连接中断| K["持续尝试重连<br/>指示灯 1 Hz 闪烁"]
    D -->|长按 On/Off [1] ≥1 s| A
    D -->|无有效交互 >60 min| A
```

设备开启后的核心行为如下：

1. 默认显示 D 表面温度，并点亮 D 表面温度指示 [8]。
2. 数字温度 [3]、温度来源图标 [6]/[7]/[8]/[13] 和温度条 [4] 应保持一致。
3. O 表面、D 表面和腔体温度在显示前应用各自独立的多项式修正；食物探针显示原始读数，不做修正。
4. 低电量、蓝牙和温标指示属于独立状态，可与当前温度来源同时显示。
5. 长按 On/Off [1] 达到 1 秒的关机操作优先于其他工作状态。

## 4. 操作流程明细

### 4.1 开机与关机

#### 开机

- 前置状态：设备关闭。
- 操作：按下 On/Off Button [1]，持续时间不限。
- 触发方式：按键一旦按下即触发，不要求释放。
- 结果：LED 显示全部以 100% 亮度开启；默认显示 D 表面温度及对应指示 [8]。

#### 手动关机

- 操作：持续按下 On/Off Button [1] 至少 1 秒。
- 触发方式：达到 1 秒即触发，不要求释放。
- 优先级：可覆盖任何当前状态并关机。
- 结果：全部显示 LED 熄灭，同时关闭蓝牙连接。

#### 空闲自动关机

- 条件：连续超过 60 分钟没有本地硬件交互，也没有成功的蓝牙连接活动。
- 结果：按手动关机流程关闭设备，以降低电池消耗。

### 4.2 蓝牙流程

#### 进入配对

- 操作：持续按下 Bluetooth Button [2] 至少 1 秒。
- 触发方式：达到 1 秒即触发，不要求释放。
- 反馈：Bluetooth Connection Indicator [11] 以 1 Hz 闪烁。
- 超时：进入配对后 2 分钟内未成功连接，则关闭蓝牙并熄灭指示灯 [11]。

#### 配对成功

- 条件：兼容的智能设备完成配对和连接。
- 反馈：Bluetooth Connection Indicator [11] 常亮。

#### 已连接状态下关闭蓝牙

- 条件：蓝牙已连接。
- 操作：持续按下 Bluetooth Button [2] 至少 10 秒。
- 结果：关闭蓝牙，Bluetooth Connection Indicator [11] 熄灭。

#### 配对状态下关闭蓝牙

- 条件：蓝牙正在配对。
- 操作：持续按下 Bluetooth Button [2] 至少 1 秒。
- 结果：退出配对并关闭蓝牙，Bluetooth Connection Indicator [11] 熄灭。

#### 连接异常与重连

- 条件：已建立的蓝牙连接意外中断。
- 反馈：Bluetooth Connection Indicator [11] 以 1 Hz 闪烁。
- 行为：设备在保持开机期间持续尝试恢复连接。
- 终止条件：重新发起配对、执行关闭蓝牙操作，或整机关闭。

### 4.3 温标切换

- 操作：快速按下 Bluetooth Button [2]。
- 默认单位：°C。
- 行为：在 °C 与 °F 之间切换。
- 反馈：°C Indicator [9] 与 °F Indicator [10] 互斥切换；Temperature Readout [3] 同步换算并更新。
- 记忆：所选温标在设备关机后仍需保留。

### 4.4 温度来源显示与切换

#### 默认温度

- 开机后默认显示 D 表面温度。
- Temperature Readout [3] 显示修正后的 D 表面温度，D Surface Temperature Indicator [8] 点亮。

#### 连接食物探针

- 操作：将食物探针的 3.5 mm 插头插入 Probe Input [5]。
- 结果：立即开始显示探针温度。
- 反馈：Probe Icon [6] 点亮；O、D 和 Cavity 指示 [7]/[8]/[13] 熄灭；Temperature Readout [3] 显示探针输入值。
- 未连接探针时：Probe Icon [6] 不亮，探针读数不参与温度来源切换。

#### 循环切换温度读数

- 操作：快速按下 On/Off Button [1]。
- 可选来源：Probe、O Surface、D Surface、Cavity。
- 限制：未连接探针时跳过 Probe，仍可在 O Surface、D Surface 和 Cavity 之间切换。
- 显示规则：任一时刻只点亮当前温度来源对应的一个图标，并在 Temperature Readout [3] 显示相应读数。

| 当前来源 | 点亮图标 | 数字显示 |
|---|---|---|
| Probe | [6] | 探针原始读数 |
| O Surface | [7] | O 表面修正后读数 |
| D Surface | [8] | D 表面修正后读数 |
| Cavity | [13] | 腔体修正后读数 |

> 原表列出了参与循环的四种来源，但没有明确规定从每一种来源短按后必然跳转到哪一种来源。固件状态机和测试用例应在实现前补充确认固定循环顺序。

### 4.5 温度修正

- 适用对象：O Surface、D Surface、Cavity。
- 方法：每个传感器使用独立的多项式系数，将原始数据修正为更接近烹饪表面/腔体实际温度的显示值。
- 不适用对象：Food Probe；探针数据直接显示，不做该项修正。
- 一致性要求：数字读数 [3]、温度来源图标和温度条 [4] 均应基于当前最终显示值。

### 4.6 温度条显示

Temperature Gauge Line [4] 与当前数字温度 [3] 对应，共 9 段，温度升高时从左到右逐段点亮。

#### O Surface / D Surface / Cavity

| 段数 | °C 阈值 |
|---:|---:|
| 1 | ≥ 30°C |
| 2 | ≥ 70°C |
| 3 | ≥ 110°C |
| 4 | ≥ 150°C |
| 5 | ≥ 190°C |
| 6 | ≥ 230°C |
| 7 | ≥ 270°C |
| 8 | ≥ 310°C |
| 9 | ≥ 350°C |

#### Food Probe

| 段数 | °C 阈值 |
|---:|---:|
| 1 | ≥ 10°C |
| 2 | ≥ 20°C |
| 3 | ≥ 30°C |
| 4 | ≥ 40°C |
| 5 | ≥ 50°C |
| 6 | ≥ 60°C |
| 7 | ≥ 70°C |
| 8 | ≥ 80°C |
| 9 | ≥ 90°C |

- 达到最高阈值后全部 9 段保持常亮，不闪烁。
- 在 °F 模式下仍显示温度条；各阈值由上述 °C 阈值换算为 °F，并四舍五入到最接近的整数。

### 4.7 低电量提示

- 触发条件：电压低于 1.1 V。
- 反馈：Low Power Indicator [12] 点亮。
- 原表未规定低电量状态下强制关机、闪烁方式或恢复迟滞值。

### 4.8 超量程显示

- 适用对象：Probe、O Surface、D Surface、Cavity 的温度读数。
- 正式流程给出的可接受范围：0–500°C。
- 高于 500°C：Temperature Readout [3] 显示 `-HI`。
- 低于 0°C：Temperature Readout [3] 显示 `-LO`。

### 4.9 设备拆出维护

- 条件：用户将设备从 fascia（面板/饰板）中拆出。
- 未连接探针：Temperature Readout [3] 显示 `---`。
- 已连接探针：继续显示探针温度数据，不应因设备被拆出而停止探针显示。

## 5. 状态与显示优先级建议

根据原表各项要求，可将显示/控制优先级整理如下：

1. **整机关机**：长按 On/Off ≥1 秒或空闲超时；关闭全部 LED 和蓝牙。
2. **维护拆出状态**：无探针时显示 `---`；有探针时继续显示探针温度。
3. **超量程状态**：当前读数越界时显示 `-HI` 或 `-LO`。
4. **探针插入事件**：插入后立即切换为探针温度。
5. **用户选择的温度来源**：通过短按 On/Off 在可用来源中切换。
6. **独立状态指示**：温标、蓝牙、低电量指示按各自状态显示。

> 此优先级是对分散流程的归纳，便于实现状态机；除“关机覆盖任何状态”外，原表没有给出完整的冲突优先级表，建议在固件规格中正式确认。

## 6. 按键判定汇总

| 按键 | 条件/持续时间 | 动作 |
|---|---|---|
| On/Off [1] | 设备关闭时按下 | 立即开机，无需等待释放 |
| On/Off [1] | 开机时快速按下 | 切换温度来源 |
| On/Off [1] | 按住 ≥1 s | 关机，覆盖其他状态 |
| Bluetooth [2] | 快速按下 | 切换 °C / °F |

## 7. 待确认事项与原型差异

以下内容来自 `Bugs and Improvements`，截至工作簿记录均未标记为解决：

1. **无探针时温度循环错误**：原型仅在连接探针时才能循环温度读数；正式要求是即使未连接探针，也应能在 O、D、Cavity 三种读数间切换。
2. **超量程实现不一致**：原型在约 450°C 以上显示 `---`，没有显示 `-HI`。正式流程写明范围为 0–500°C；问题清单又提出将下限设为 -20°C、上限设为 500°C。下限究竟采用 0°C 还是 -20°C，需要产品方最终确认。
3. **拆出设备后的探针显示错误**：原型在模块拆出壳体后不显示探针温度；正式要求是只要探针仍连接，就继续显示探针数据。
4. **温度修正尚待实现/校准**：测试发现各内置传感器原始值与实际表面/空气温度不一致，需要分别配置修正系数。问题清单还提出系数应支持无线更新，但这一点未写入正式 `Operation Process`，需单独确认。
5. **按键边界存在歧义**：从关机状态持续按住 On/Off 时，开机在按下瞬间触发，而关机在持续 1 秒时又可覆盖任何状态；需明确一次持续按压是否可能造成“先开机、后关机”，以及是否要求释放后才能开始新的长按判定。
6. **蓝牙按键状态依赖**：Bluetooth 长按 ≥1 秒在蓝牙关闭时用于进入配对，在配对状态时用于关闭蓝牙；实现必须先判断当前蓝牙状态，避免同一次按压重复触发相反动作。

## 8. 建议的验收重点

- 验证按键动作均按达到时长触发，不依赖释放事件。
- 验证关机命令能从温度显示、配对、已连接和重连等任意状态生效。
- 验证无探针时仍可循环 O、D、Cavity，且不会出现 Probe 选项或 Probe 图标。
- 验证探针插入会立即切换显示，设备拆出后仍能继续显示探针温度。
- 验证 °C/°F 选择掉电保存，且数字温度与温度条阈值同步换算。
- 分别验证三路内置传感器的多项式修正，确认探针不参与修正。
- 验证 `-HI`、`-LO`、`---` 三种特殊显示不会互相混淆。
- 验证蓝牙配对 2 分钟超时、断线持续重连、配对态关闭和连接态 10 秒关闭。
- 验证低于 1.1 V 时低电量图标点亮，并确认是否需要迟滞或恢复阈值。
