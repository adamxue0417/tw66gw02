# 新交付检查表

[返回交付入口](README.md)

每次交付建立新目录，建议名称为 `来源_工厂版本-to-OTA版本_Bootloader迭代_DEV或正式状态_日期`。保留旧快照，不用新构建静默覆盖旧包。

| 必填项 | 记录内容 |
| --- | --- |
| 来源 | 源工程路径、准确提交号和未提交差异；提交不明确时保存逐文件源码指纹，说明其与产物的验证关系 |
| 版本 | 工厂版本、OTA 目标版本、安全版本；快照号不作为固件版本 |
| 引导与分区 | Bootloader 迭代、boot_api_version、App 起址、槽容量、签名格式及 DEV/正式属性 |
| 适配组合 | MCU、板卡修订、BLE 模块/固件、手机 APP 标识/版本/构建号、协议版本 |
| 构建环境 | 编译器完整版本、构建命令、必要依赖、原始构建日志 |
| 文件 | Factory_Flash 完整镜像、App_Upload OTA 与 manifest、Debug_Only 裸应用；逐文件 SHA-256 |
| 验证记录 | 日期、执行人/环境、结果和日志；历史结果与本次结果分开；未执行写 PENDING |
| 实机结果 | 烧录启动、版本上报、BLE、OTA/回滚及该版本相关功能；记录硬件与手机组合 |

归档前核对 OTA 长度、SHA-256、CRC、签名策略、manifest 和 Factory 中的 Bootloader/App 内容。零签名占位包与 DEV 密钥签名包均保持开发标识；私钥和本地依赖环境不进入交付目录。

SHA256SUMS.txt 覆盖除自身以外的全包文件；交付 manifest 记录原文件来源。说明、指纹和验证记录同样纳入校验。完成后更新 README 与 JSON 清单，未知信息明确写“待核实”。

中间文件可按工程忽略规则保留。清理前明确目录及可重建性、检查 Git 跟踪情况、建立经过解压校验的恢复包；不要按扩展名扫描整个工作区后直接删除。
